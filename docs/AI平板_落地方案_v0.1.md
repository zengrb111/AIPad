# AI 平板（AI Pad Mate）落地方案 v0.1

> 目标：在传统平板基础上加"人体感应 + 主动发起语音聊天"能力
> 前提：团队无硬件开发经验
> 日期：2026-11-02

---

## 0. 一句话结论

**第一阶段不要做平板。做一个 200 块的感应盒子，配一台 1200 块的现成安卓平板。**

理由在下面，但核心就一句：**你真正要验证的不是"能不能造出平板"，而是"人靠近时机器主动开口，人会不会觉得舒服"。** 后者用 2 周和 1500 块就能验证，前者要 50 万和一年，而且验证不了这件事。

---

## 1. 先纠一个方向：平板不是你的产品

### 1.1 自研一台平板真实成本

| 环节 | 内容 | 成本（元） | 周期 |
|---|---|---|---|
| 方案/主板 | RK3588 或全志 A523 核心板 + 底板设计 | 3–8 万 | 4–6 周 |
| 结构/模具 | 外壳 ID + MD + 手板 + 钢模 | 3–10 万 | 6–10 周 |
| 屏幕模组 | 10.1"/11" LCD + 触摸，需匹配驱动 | 单台 200–350 | 2 周（找现货） |
| 电池/电源 | 电芯 + BMS + 适配器 | 单台 60–120 | 3 周 |
| 认证 | 3C（强制）+ SRRC（WiFi/蓝牙）+ CTA（如需 4G） | 3–6 万 | 8–12 周 |
| 打样/试产 | 首批 50–100 台，含 SMT、组装、良率损耗 | 8–15 万 | 6–8 周 |
| **合计** | | **约 25–50 万** | **6–9 个月** |

而且做出来的东西：性能不如小米平板 6（¥1300）、屏幕不如、系统优化不如、售后体系为零。**在"平板"这个维度上，你不可能赢。**

### 1.2 你的差异化根本不在平板

差异化只在两件事上：
1. **人体存在感知**（谁在、离多远、待多久）
2. **主动发起对话的分寸感**（什么时候开口、说什么、被无视了怎么退）

这两件事，一个 ESP32 加一块毫米波雷达就解决了，跟平板本身没关系。平板只是个"屏幕 + 喇叭 + 麦克风 + 算力"的载体，市面上 1200 块的产品已经把这个载体做到 90 分。

### 1.3 那什么时候才该做一体机

明确三个信号，全部满足才考虑：

- [ ] 已有 ≥ 200 台真实设备在用户家里跑满 3 个月
- [ ] 主动搭话的接受率 > 60%（用户不反感、有回应）
- [ ] 有客户明确说"我愿意为一体化外观多付 800 块"，且已付定金

在此之前，一体机都是在为一个没验证过的需求烧钱。

## 2. 产品定义：先把"主动"这件事想清楚

技术是简单的，分寸感才是产品。**主动搭话的失败模式不是"说错话"，是"烦人"。**

### 2.1 目标场景（假设，需确认）

按 OPC 生态现有主线推断，默认锁定 **家庭陪伴**：客厅/卧室/床头，单人独处，使用者在 1–3 米内静态活动。

> ⚠️ 如果是**办公桌面**场景（人在桌前工作），拾音距离、主动频率、话术风格全部要改，第 6 节参数需重算。

### 2.2 主动搭话的五条硬规则

这些是产品能不能活下来的关键，比硬件选型重要得多。

| 规则 | 参数 | 为什么 |
|---|---|---|
| **不接路人** | 连续在场 ≥ 8 秒才触发 | PIR 会被人走过触发，导致家里有人走动就自言自语，这是最劝退的失败 |
| **限频** | 每小时 ≤ 1 次主动；每天 ≤ 4 次 | 主动超过这个密度，从"贴心"变"监视" |
| **限时** | 22:00–08:00 不主动开口 | 半夜说话是灾难级体验，且影响家人 |
| **可忽略** | 搭话后 5 秒无回应 → 静默退回待机，**不重复、不追问** | 允许用户不理它，才敢让它开口 |
| **低压力话术** | 只做陈述/邀请，不提问式索取 | "今天回来得早" ✅ ／ "你去哪儿了？" ❌ |

### 2.3 三个必须做对的交互细节

1. **招呼语必须本地预生成**。走在线 TTS，从"检测到人"到"出声"会有 1–2 秒空白，人已经走过去了。预生成 mp3 存在本地，触发即播，延迟 < 300ms。
2. **第一句话不要求用户回应**。开场是"播报式"的（天气/时间/一句闲话），说完才开麦。降低用户的心理负担。
3. **必须有物理静音开关**。摄像头 + 麦克风常开的设备，没有物理开关会被家人排斥（尤其卧室场景）。

## 3. 技术架构

### 3.1 三层结构

```
┌─────────────────────────────────────────────────┐
│  感应层（外挂盒子，¥150）                          │
│  毫米波雷达 LD2410C → ESP32-S3 → WiFi/BLE        │
│  输出：有人/无人、距离、静止/移动、持续时长          │
└──────────────────────┬──────────────────────────┘
                       │ MQTT / WebSocket / BLE HID
┌──────────────────────▼──────────────────────────┐
│  载体层（现成安卓平板，¥1200）                     │
│  常驻 App：状态机 + 音频 + UI                      │
│  屏幕常亮黑遮罩 ／ 或 BLE 键盘事件唤醒               │
└──────────────────────┬──────────────────────────┘
                       │ HTTPS / WebSocket 流式
┌──────────────────────▼──────────────────────────┐
│  云/边层（复用现有后端）                            │
│  ASR → LLM → TTS，流式；复用 AIMemory 账号体系      │
└─────────────────────────────────────────────────┘
```

### 3.2 感应层选型（这是唯一需要"懂硬件"的地方，但只是一块开发板）

| 器件 | 型号 | 价格 | 说明 |
|---|---|---|---|
| 人体存在雷达 | **海凌科 HLK-LD2410C** | ¥35–55 | 24GHz 毫米波，**能检测静止的人**（呼吸微动）。这是关键——PIR 只能测移动，人坐着不动它会认为没人 |
| 主控 | **ESP32-S3-DevKitC** | ¥40–60 | 自带 WiFi + BLE，Arduino/ESP-IDF 都能写，教程海量 |
| 备用方案 | HLK-LD2450 | ¥70–90 | 多一个"方位角"，能判断人在左/右，做"转头看人"有用 |
| 外壳 | 3D 打印 | ¥30–50 | 第一阶段别开模 |

**为什么不用摄像头做人脸检测？**
摄像头方案（视觉判定）信息量最大，但：① 卧室/客厅装摄像头有强烈隐私抵触；② 需要算力，平板跑会发热耗电；③ 光线差时失效。**毫米波雷达不采集图像，只有"有没有人、多远"，这在家庭场景是决定性的优势**——这句话本身就是产品的卖点。

### 3.3 通信方式：三个方案，按阶段选

| 方案 | 实现 | 优点 | 缺点 | 用在 |
|---|---|---|---|---|
| **A. WiFi + MQTT** | ESP32 连家里 WiFi，发布到 MQTT broker，平板 App 订阅 | 最简单，1 天能跑通 | App 需常驻后台，安卓会杀进程 | **P1 验证阶段** ✅ |
| **B. BLE HID 键盘** | ESP32 冒充蓝牙键盘，检测到人 → 发一个按键 | **平板零改造，系统级唤醒，App 杀不掉** | 需要处理配对，iPhone/iPad 不支持 | **P2 产品化** ✅ 推荐 |
| **C. USB-OTG 串口** | 有线连 | 最稳 | 平板只有 1 个口，充电冲突 | 不推荐 |

**B 方案是隐藏杀招**：ESP32 通过 BLE 模拟蓝牙键盘，检测到人靠近就"按一下某个键"。平板系统会把它当成真实键盘输入——**能唤醒屏幕、能穿透后台限制、App 不需要任何保活技巧**。这是绕开 Android 后台限制最干净的办法。

### 3.4 载体层：平板怎么选

| 要求 | 说明 |
|---|---|
| 系统 | Android 11+（需要有 `AcousticEchoCanceler` API） |
| 尺寸 | 10–11 寸（太小远场看不清，太大不像家居产品） |
| 关键要求 | **支持"充电时保持屏幕常亮"**（开发者选项里有） |
| 推荐 | Redmi Pad SE 11"（¥899）／ 小米平板 6（¥1299）／ 二手 iPad（不推荐，后台限制更严） |

**P1 阶段直接用你手上任何一台安卓平板，成本 0。**

## 4. 软件链路 & 五个真实的坑

### 4.1 主链路

```
雷达: 有人进入 → 距离 0.5–3m → 持续 8s
   ↓
App: 状态机 待机 → 唤醒 → 播招呼语(本地mp3)
   ↓
开麦 → VAD 检测用户说话 → 流式 ASR
   ↓
LLM（带上下文 + 人设）→ 流式 TTS → 播放
   ↓
结束 → 冷却期（≥1h 才允许下次主动）→ 待机
```

### 4.2 五个必踩的坑（按踩坑概率排序）

**坑 1：自问自答（AEC 问题）—— 概率 100%**
平板外放 TTS 时，麦克风会把自己的声音收进去，AI 听到自己说话然后回应自己。
- 正解：录音用 `MediaRecorder.AudioSource.VOICE_COMMUNICATION`（系统会启用硬件回声消除）
- 兜底：**半双工**——TTS 播放期间强制关麦，播完再开。代价是不能打断，但 100% 有效
- 进阶：外接带 AEC 的麦克风阵列

**坑 2：息屏后叫不醒 —— 概率 90%**
Android Doze 模式会让后台 App 完全休眠，WiFi 消息收不到。
- 正解 A（简单）：插电 + 屏幕常亮 + 全屏黑色遮罩（假息屏）。功耗约 3–5W，白天看不出，晚上有微光
- 正解 B（干净）：BLE HID 方案，让 ESP32 发按键唤醒
- 不要指望：`WakeLock` + 电池优化白名单，国产 ROM（MIUI/HyperOS）照样杀

**坑 3：远场听不清 —— 概率 80%**
平板内置麦克风在 3 米外信噪比很差，尤其有电视/空调底噪时。
- P1 阶段：把距离限制在 **1.5 米内**验证（床头、书桌场景），先绕开
- P2 阶段：外接 USB 全向麦（¥200–400）或 2 麦阵列
- **别在 P1 解决这个，它是硬件问题，会拖死验证节奏**

**坑 4：长期插电电池鼓包 —— 概率 70%**
24 小时插电的锂电池，半年到一年会鼓包，是安全隐患。
- 正解：硬件加一个"充电到 60% 断电"的模块（¥30），或选支持"电池保护模式"的机型
- 临时：每 3 个月检查一次，作为内测机的运维项

**坑 5：误唤醒 / 人在但不想说话 —— 概率 60%**
人在房间里走动、看电视、打电话，机器误判为"可以搭话"。
- 正解：多重条件——在场时长 + 距离区间（0.5–2m，太远不搭话）+ 环境噪音低于阈值 + 未处于冷却期
- 加一个"今天不想聊"的物理/语音快捷指令

## 5. 三阶段落地路线

### P1｜2 周｜¥1500｜验证"主动搭话"这件事本身

| 项 | 内容 |
|---|---|
| 硬件 | 现有安卓平板 + ESP32-S3 + LD2410C + 杜邦线 + 3D 打印壳 |
| 软件 | Android App：MQTT 订阅 + 状态机 + 本地招呼语音 + 调云端 ASR/LLM/TTS |
| 场景 | 自己家，床头或书桌，跑 7 天 |
| **通过标准** | ① 每天主动搭话 ≥2 次且无一次觉得烦<br>② 招呼语到出声 < 500ms<br>③ 家人不反对它待在客厅 |
| 失败信号 | 3 天内你自己开始想关掉它 → 需求不成立，止损 |

**这 2 周花的钱，抵得上后面 50 万的决策质量。**

### P2｜4–6 周｜¥2 万｜做成能给别人用的样子

| 项 | 内容 |
|---|---|
| 硬件 | 小批量 10–20 套：定制 PCB（把 ESP32+雷达做在一块板上，¥2000 打样）+ 3D 打印/小批量外壳 |
| 通信 | 切 BLE HID，解决后台唤醒 |
| 音频 | 外接 USB 麦克风，解决远场；加充电保护模块 |
| 软件 | 加账号体系（复用 AIMemory）、设备管理后台、OTA 升级 |
| 验证 | 10 户真实家庭，跑 30 天，收集"主动搭话接受率" |

**关键指标：接受率 > 60%（有回应 / 主动次数）。** 低于这个数，说明"主动"这个卖点是假的。

### P3｜3–4 个月｜¥8–15 万｜小批量产品化

只做一件事：**把外壳和结构做好看**。主板继续用现成方案（RK3588 核心板 + 定制底板）。

- 手板 → 修模 → 小批量 100–200 台
- 认证：3C + SRRC（先做这两个，4G 版再说）
- **依然不要自己设计屏幕和电池**，找整机方案商（深圳一堆，搜"RK3588 平板方案商"），你出 ID 和软件，他们出硬件

## 7. 风险清单

| 风险 | 影响 | 对策 |
|---|---|---|
| **隐私抵触** | 家庭场景最大阻力，尤其有摄像头 | 不用摄像头；物理静音开关；本地处理优先；把"不采集图像"做成卖点 |
| **新鲜感衰减** | 用两周就不玩了（智能音箱的共同死法） | 内容要每天不同（接 AIMemory 的回忆录内容库）；主动搭话要"有事说"而不是"找话说" |
| **家人反对** | 一个会说话的设备在客厅，家人未必接受 | P1 就要在真实家庭测，不能自己一个人测 |
| **供应链踩坑** | 方案商报价不透明、模具反复改 | P3 前先找 3 家比价，要求看已量产案例 |
| **和 AI Worker / AIMemory 的关系** | 三条线分散精力 | AIPad 的内容必须来自 AIMemory，硬件只是 AIMemory 的一个"出口"，不独立建内容体系 |

## 附：为什么我建议"先别做硬件"

你已有的资产是 **AI Worker（生产）+ AIMemory（内容）+ 后端能力**。AIPad 的价值是给这套东西加一个"物理出口"——让 AI 从屏幕里走出来，坐在客厅里。

但"出口"的价值取决于"里面的东西"值不值得被听见。**先用 1500 块验证"人愿不愿意听"，再决定要不要花 50 万做一个更好看的喇叭。**
