# 相框 Demo

给爸妈的相框：子女在手机上传照片和视频、留语音，老人那边的相框自己播；老人点一下屏幕就能说句话回去。

AI 会先看懂照片，用一段口语讲给老人听（"您看这张，小满扶着沙发站着，手里还攥着半块饼干"），视频还会把里面的说话识别成字幕。子女传图时可以一个字都不写。

**没有人体感应**，按你的要求先不做。

两个 APK 都编好了，在 `release/`，装法见 **[docs/平板安装指南.md](docs/平板安装指南.md)**：

| 文件 | 装在哪 | 包名 |
|---|---|---|
| `相框-v1.0.apk` | 家里的平板 | `cafe.aimemory.frame` |
| `爸妈的相框-v1.0.apk` | 子女的手机 | `cafe.aimemory.family` |

包名不同，**可以同时装在一台机器上**。

- **iPad**：Safari 添加到主屏幕 + 引导式访问（iOS 打不了真包，见安装指南开头）
- **Android**：装 APK，或者用 Chrome 的「安装应用」，或者用 Fully Kiosk Browser 做专用相框
- **改完代码重新打包**：`npm run apk`（一次出两个包）

## 一、跑起来

```bash
npm install
npm run build
npm start
```

启动后终端会打出两个地址，手机上打开「子女端」那个，相框上打开「相框端」那个：

```
子女端   http://192.168.x.x:4000/family   ← 手机上打开
相框端   http://192.168.x.x:4000/frame    ← 相框上打开
```

想先看效果不想手传照片，可以灌一份演示数据（素材在 `tmp/`）：

```bash
npm run seed
```

**想开 AI 解说**，启动前给三个环境变量：

```bash
AI_API_KEY=你的key AI_MODEL=gpt-4o-mini npm start
```

不配也能跑，只是相框只会念子女留的那句话，界面会标明「未配置 AI」。

## 二、两个界面分别做什么

### 子女端 `/family`

- 传照片或视频，配一句话（也可以一个字不写，AI 会自己讲）
- 能看到 AI 给这张照片写的解说，不满意点「换个说法」重新生成
- 视频会显示 AI 识别出来的字幕，和识别段数
- 每张照片下面能看到爸妈的语音留言，带「新」标记
- 对某张照片语音回复，或者不配照片直接留一句
- 右上角「看相框」可以新窗口打开相框端，方便一台电脑上对照调试

### 相框端 `/frame`

- 照片和视频混着自动轮播，18 秒一项
- 照片全屏铺满，缓慢推近；视频显示封面帧 + 播放按钮，**点一下才播**（避免一进来就出声吵到人）
- 竖屏视频不会裁画面，两侧用同一张图模糊垫底，不留黑边
- 轮到某项时 AI 解说自动播，文字同步显示在底部
- 视频播放中按时间轴显示字幕
- **点屏幕任意处 → 出现大按钮 → 点一下开始说 → 再说一下结束**，自动发出去
- 31 秒不操作自动退出，防止误触
- 收到子女语音会自动播放，播完标记已听
- 首次打开有个「轻触屏幕」的解锁页，原因见下面的坑 2

录音是「点一下开始、再点一下结束」，不是按住说话——按着不放对老人手不稳的情况不友好。

## 三、AI 解说 / 语音合成 / 视频字幕

### 解说文字（需要配 key，走 OpenAI 兼容接口）

```
AI_BASE_URL   默认 https://api.openai.com/v1
AI_API_KEY    必填
AI_MODEL      视觉模型，如 gpt-4o-mini / qwen-vl-max / glm-4v
```

提示词里写死了几条规则，核心是**不许编**：不编姓名年龄职业日期地点，看不准的说"看着像"，不确定就不说。**给老人念错信息比不念更糟**——他会当真，还会转述给别人。

子女留的那句话会作为事实依据喂给模型，所以「写了」比「不写」准，但不写也能跑。

生成的解说是 2–3 句、70 字内，附带一句预生成的语音。子女端能看到全文，不满意点「换个说法」重生成。

**文字和语音都在上传时生成一次，之后靠 SSE 推给相框**：`/api/events` 一条长连接，
解说一生成完，相框几百毫秒内就收到并开始播。相框端**不做任何识别或合成**——
它只负责播放服务端给的 mp3，所以音色统一、老平板也不卡。

### 语音合成（本机跑，不要 key）

用 `msedge-tts`，默认音色 `zh-CN-XiaoxiaoNeural`（晓晓），语速 -8%（比常速慢一点，老人听得清）。生成一次存成 mp3，所有设备播同一个文件，不用每个相框自己合成。

```bash
TTS_VOICE=zh-CN-YunxiNeural   # 想换男声，可选 Yunxi/Yunjian 等
TTS_RATE=-8%                   # 语速，负数是慢
```

合成失败不影响文字，相框端会退回浏览器朗读（有中文语音包才出声，没有就只显示字幕）。

### 视频字幕（本机跑，不要 key）

上传视频后自动做三件事：转码压到 720p 左右、抽第 1 秒做封面、把里面的说话识别成带时间戳的字幕。

```bash
ASR_MODEL=Xenova/whisper-base   # 默认；想更准换 Xenova/whisper-small（慢 3 倍、模型 500MB）
ASR_OFF=1                       # 关掉字幕
HF_MIRROR=https://hf-mirror.com # 模型下载镜像，国内直连 huggingface 基本不通
```

首次运行会下载约 150MB 模型，之后走本地缓存。

**能力边界要说清楚**：

| 素材 | 结果 |
|---|---|
| 正常说话（家庭视频） | 可用。实测 8 秒音频 2.4 秒识别完，只错个别字 |
| 唱歌 / 演唱会 / 强背景音乐 | **不可用，会被判定为"不像正常说话"直接不出字幕** |
| 没有人声的视频 | 不出字幕，也不报错 |

唱歌识别不了是 whisper 这类模型的固有特性，不是参数没调好。所以加了一道质量判断（4-gram 重复率 + 用字集中度）：**宁可不出字幕，也不给老人看胡说八道**。判断掉的时候子女端会看到"这段声音不像正常说话"。

## 四、三个必须知道的坑

### 坑 1：局域网 http 下录音会被浏览器禁用

浏览器只在 **https** 或 **localhost** 下允许拿麦克风。手机和相框是另一台设备，只能走 IP，所以 http 会直接拒绝录音（`getUserMedia` 失败）。

正式用之前先生成证书：

```bash
npm run cert
npm start
```

这会用本机 IP 生成一张自签证书，服务自动切到 https。浏览器第一次打开会报「不安全」，点「高级 → 继续前往」就行，之后录音正常。

> Windows 需要 openssl，装了 Git for Windows 就有。没有的话用 WSL 生成后把 `certs/` 拷过来。

如果暂时只在**本机**测，用 `http://localhost:4000` 是可以录音的，不用折腾证书。

### 坑 2：浏览器不允许"没有交互就出声"

相框一打开页面就自己讲话，会被浏览器的自动播放策略拦掉。这是浏览器的规定，不是 bug。

所以 `/frame` 上做了一个「轻触屏幕」的解锁页：装好后点一下，之后这一整个会话都能自动播。相框重启或刷新后需要再点一次。

想彻底免掉这一步：

- **用 Fully Kiosk Browser**，设置里打开「自动播放媒体」
- 或者打包成 App，WebView 里设 `mediaPlaybackRequiresUserGesture = false`

### 坑 3：安卓相框可能装不了 App

买之前一定要问客服三个问题：

1. 是 Android 系统吗？版本多少？（至少要 7.0）
2. 能装第三方 APK 吗？允许「未知来源应用」吗？
3. 支持开机自启某个应用吗？

**建议直接买「安卓云相框」「安卓广告机」这类**，本质是一块能装 App 的安卓屏，比消费级电子相框好搞。

## 五、装到相框上

### 方法 A：装 Fully Kiosk Browser（推荐，最快）

这是安卓 Kiosk 场景的标准方案，免费版够用，专治"相框就该一直显示一个页面"：

1. 相框上装 Fully Kiosk Browser
2. 起始页填 `https://你的IP:4000/frame`
3. 设置里打开：屏幕常亮、开机自启、隐藏状态栏、禁用返回键、允许麦克风

这比自己写壳 App 省事得多，也绕开了「息屏后叫不醒」和「被系统杀后台」两个问题。

### 方法 B：打包成 APK

如果你想要一个独立的 App 图标，用 Capacitor 把 `dist/` 包成 APK：

```bash
npm i -D @capacitor/cli @capacitor/core @capacitor/android
npx cap init 相框 com.yourco.frame --web-dir=dist
npx cap add android
npx cap sync
```

然后在 Android Studio 里给 `MainActivity` 加上保持屏幕常亮和全屏的几行代码。这条路和 AI Memory 现在的技术栈一致，能复用。

### 方法 C：先用浏览器凑合

相框自带浏览器打开 `/frame`，加书签，手动设成常亮。能用，但重启不会自动回来。

## 六、代码结构

```
server/
  index.js      Express 服务、上传接口、轮询接口、https 判断
  store.js      JSON 文件存储（原子写，不会写坏）
  media.js      ffmpeg：图片缩到 1600、语音转 m4a、视频转 720p + 抽封面
  ai.js         调视觉模型写解说 + 本地合成语音
  asr.js        本地 whisper 出视频字幕（含乱码判断）
src/
  frame/        FrameApp.tsx    相框端
  family/       FamilyApp.tsx   子女端
  lib/
    api.ts      接口封装
    recorder.ts 录音（自动挑浏览器支持的格式）
scripts/
  seed.mjs      灌演示数据（素材在 tmp/）
  gen-cert.mjs  生成自签证书
  shot.mjs      精确截图（Chrome headless 在 Windows 上忽略 --window-size，必须走 CDP 设视口）
  measure.mjs   量页面各容器实际坐标，排查布局用
data/           运行时生成，照片、视频、语音都在这里
```

### 为什么语音要转码

安卓录出来是 `webm/opus`，iPhone 播不了；iPhone 录的是 `mp4`。所以后端统一用 ffmpeg 转成 `m4a`（aac 64k 16kHz 单声道），两端都能播，体积压到原来的 1/5。

图片同理，原图动辄 5MB，统一缩到最长边 1600 转 jpg，相框加载才不卡。

**没有 ffmpeg 也能跑**，只是原文件直存，播放兼容性会差一些。

### 数据长什么样

`data/db.json`：

```json
{
  "photos": [
    { "id": "uuid", "file": "xxx.jpg", "caption": "上周包了饺子", "from": "小彬", "createdAt": 1793608510812 }
  ],
  "comments": [
    { "id": "uuid", "photoId": "uuid", "from": "parent", "audio": "xxx.m4a", "duration": 5, "heard": false, "createdAt": 1793608519250 }
  ]
}
```

`from` 只有两个值：`parent`（相框那头）和 `child`（手机那头）。

## 七、这一版故意没做的

| 没做 | 为什么 |
|---|---|
| 人体感应 | 你说了先不考虑。感应的作用是「何时说」，不是「说什么」 |
| 字幕只认中文 | whisper 多语言模型能认英文，但产品场景用不上，没配 |
| 推送通知 | 用 5 秒轮询顶着了。真上手再换推送 |
| 多设备/账号 | 现在是单家庭单设备，直接从 URL 区分两端 |
| 删除照片 | 接口有了（`DELETE /api/photos/:id`），界面上没放，怕误删 |

## 八、下一步建议

1. **先让爸妈用一周**，看三个事：它自己播的时候会不会烦、点屏幕说话会不会用、子女端会不会天天传
2. 一周后如果成立，加**人体感应**（ESP32 + LD2410C，外挂一个盒子，不用改相框）
3. 再然后是 **AI 讲解**——照片进来先让模型看一眼，生成一句"这张里有谁、在哪、可能是什么时候"，用 TTS 念出来。这是 heyparent / HeyBondi 真正在卖的东西

第 3 步才是分水岭：前面是"能传照片的屏"，加了 AI 讲解才是"会讲话的相框"。
